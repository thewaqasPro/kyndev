Brand "K" Preloader Morph & Live Debugger

Complete technical guide to the branded KYNDEV "K" loading animation, zero-seam rasterization engine, and the interactive real-time developer debugger.

⚡ Quick Debug Key
You can freeze and inspect the K morph at any time on your local server by appending ?debug-k to the URL, for example: http://localhost:4321/?debug-k.

1. Architectural Overview

The site's preloader and page-to-page route transitions are rendered onto an HTML5 2D canvas overlay (<canvas id="transition-overlay">) managed by src/scripts/runtime/ui/TransitionOverlay.js.

The transition sequence operates in 3 distinct stages:

  1. Asset Loading Capsule (loadBarRatio): As assets ingest, a minimalist horizontal progress pill grows from 0% to 100%.
  2. Geometric "K" Origami Morph (lineTransformRatio / showTextRatio): The progress bar unfolds into the 4 constituent strokes of the KYNDEV "K" symbol.
  3. Unified Dissolve (revealRatio / hideTextRatio): The K zooms forward toward the camera while smoothly fading to transparent in unison with the dark backdrop, revealing the interactive 3D hero page beneath.

2. How to Use the Live Debugger (?debug-k)

A real-time developer HUD is built directly into TransitionOverlay.js. It allows you to freeze the animation, manually scrub through morph ratios, inspect border radii, and test transitions without reloading the page.

Activating the HUD

There are two ways to activate the panel:

  • URL Query Parameter (Recommended): Add ?debug-k to any route, such as http://localhost:4321/?debug-k or http://localhost:4321/about?debug-k.
  • DevTools Console: Open your browser's developer console and enter: 
    window.DEBUG_K = { active: true, morph: 1.0, reveal: 0.0, radius: 0.18, angle: 0.233 };

3. Mathematical Stroke Geometry & Alignment

The letter "K" is assembled from 4 rotating rectangle segments. All 4 strokes pivot around a shared central anchor point: 

const jX = -0.6; // Shared horizontal junction point
const jY = 0;    // Vertical center line
Stroke Segment Offset (sx, sy) Size (sw, sh) Rotation Formula Corner Radii [tl, tr, br, bl]
1. Upper Stem (-2.1, -0.5) (2.1, 1) +effMorph * (Math.PI * 0.5) (+90°) [strokeRadius, 0, 0, strokeRadius]
2. Lower Stem (-2.1, -0.5) (2.1, 1) -effMorph * (Math.PI * 0.5) (-90°) [strokeRadius, 0, 0, strokeRadius]
3. Upper Wing (0, -0.5) (3.2, 1) -effMorph * (Math.PI * 0.233) (~ -42°) [0, strokeRadius, strokeRadius, 0]
4. Lower Wing (0, -0.5) (3.2, 1) +effMorph * (Math.PI * 0.233) (~ +42°) [0, strokeRadius, strokeRadius, 0]

4. Why Zero Radius at the Center Junction Matters

In previous builds, applying corner radius uniformly across all 4 corners of every stroke caused the vertical spine to appear divided in the middle: where the upper half and lower half met at y = 0, the rounded corners created inward notches and gaps.

The Continuous Column Fix
By assigning [strokeRadius, 0, 0, strokeRadius], the meeting ends at the center junction have a radius of 0 (completely square), while the outer ends (the very top of the letter and the very bottom) retain the smooth rounding. This makes the vertical column look like a single seamless, solid pillar.

5. Offscreen Canvas Rasterization (_kCanvas)

When multiple shapes overlap, drawing them with semi-transparency (e.g., during the fade-out dissolve) causes the overlapping regions to double in opacity, creating dark lines or "seams".

To solve this permanently, TransitionOverlay.js renders all 4 strokes at solid 100% white onto an isolated offscreen canvas (this._kCanvas, 512×512):

src/scripts/runtime/ui/TransitionOverlay.js 
// 1. Draw all 4 strokes onto isolated offscreen canvas at 100% solid opacity
const kCtx = this._kCtx;
kCtx.clearRect(0, 0, kSize, kSize);
// ... draw segments with fillStyle = "#ffffff" ...

// 2. Composite the flattened glyph onto the main viewport with unified globalAlpha
u.save();
u.globalCompositeOperation = "source-over";
u.globalAlpha = kAlpha; // Unified fade-out
u.drawImage(kCanvas, -kSize * 0.5 / kScale, -kSize * 0.5 / kScale, kSize / kScale, kSize / kScale);
u.restore();

6. How to Modify the Letter in the Future

All parameters can be easily adjusted in src/scripts/runtime/ui/TransitionOverlay.js:

A. Changing Diagonal Wing Angle

To change how wide or narrow the K wings open, edit armAngle:

// Default: 0.233 (~42 degrees)
const armAngle = this.debug.active ? this.debug.angle : 0.233;

// For steeper wings (narrower spread): 0.18 (~32 degrees)
// For flatter wings (wider spread): 0.25 (45 degrees)

B. Changing Arm or Stem Lengths

To make the wings longer or the vertical spine taller, edit the sw (width) parameter in drawSegment:

// Make the diagonal wings longer: change 3.2 to 3.6
drawSegment(0, -0.5, 3.6, 1, armRadii, effMorph * (Math.PI * armAngle));

// Make the vertical stem taller: change 2.1 to 2.4
drawSegment(-2.4, -0.5, 2.4, 1, stemRadii, effMorph * Math.PI * 0.5);

C. Changing Stroke Thickness

To increase the stroke weight (e.g. from 1.0 to 1.2 units):

// Set height to 1.2 and vertical center offset to -0.6
drawSegment(sx, -0.6, sw, 1.2, rad, angle);

D. Changing Transition Speeds

Route navigation speeds are managed in TransitionOverlay.update(e):

// Increase multipliers for faster transitions, decrease for slower
this.showTextRatio = Math.min(1, this.showTextRatio + e * 1.5);
this.waitTextRatio = Math.min(1, this.waitTextRatio + e * 2.8);
this.hideTextRatio = Math.min(1, this.hideTextRatio + e * 1.5);
