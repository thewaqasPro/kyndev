Marketing Tools Hero 3D Architecture & Customization Guide

Comprehensive guide for configuring marketing tool chips, swapping image and vector icons, fine-tuning 3D physics forces, adjusting speeds and tumbling behavior, and customizing the WebGL background shade transitions.

1. Section & File Architecture

The 3D Marketing Tools Hero section simulates 12 floating, colliding, and tumble-responsive brand chips within a framed deck container. The implementation is cleanly separated across four key files:

File Path Role & Responsibility
src/components/home/HeroTools/HeroToolsScene.ts Core 3D Engine: Three.js setup, tool definitions, vector icon rendering, physics loop, collision solver, and WebGL vignette background shader.
src/components/home/HeroTools/HeroTools.astro Astro Component: HTML structure, HUD card, action buttons, layout toggle banner, and client hydration scripts.
src/components/home/HeroTools/heroTools.css Styling: Pure white canvas styling, 40/60 split grid, responsive stacking for mobile/tablets, and HUD badge glassmorphism.
src/scripts/runtime/sections/HeroToolsSection.js Runtime Controller: Manages lifecycle hooks (preInit, init, resize, hide), layout switching, and sound dispatch.

2. Customizing & Swapping Chip Icons

All chip configurations live inside HeroToolsScene.ts in the getToolConfigs() method. Each tool is defined by a MarketingToolConfig object: 

interface MarketingToolConfig {
  id: string;                                                      // Unique key (e.g. 'google-ads')
  name: string;                                                    // Front badge title
  subtitle: string;                                                // Front badge subtext / tag
  primaryColor: string;                                            // Accent & border glow color
  accentColor: string;                                             // Metallic rim color
  metalness: number;                                               // Rim reflectivity (0.0 - 1.0)
  roughness: number;                                               // Rim sheen (0.0 - 1.0)
  radius: number;                                                  // 3D Disc radius (default: 1.24 - 1.30)
  thickness: number;                                               // 3D Disc depth (default: 0.30 - 0.34)
  drawIcon: (ctx: CanvasRenderingContext2D, size: number) => void; // Vector icon drawer
}

Option A: Drawing with Canvas 2D Vector Paths (Recommended)

The built-in vector drawer produces crisp, resolution-independent icons at any zoom or angle without network latency or image loading glitches: 

{
  id: 'my-custom-tool',
  name: 'OpenAI',
  subtitle: 'LLM & Generative Intelligence',
  primaryColor: '#10A37F',
  accentColor: '#008764',
  metalness: 0.45,
  roughness: 0.22,
  radius: 1.26,
  thickness: 0.32,
  drawIcon: (ctx, size) => {
    const c = size / 2;
    const r = size * 0.35;
    ctx.save();
    ctx.translate(c, c);
    
    // Draw your vector path here
    ctx.fillStyle = '#10A37F';
    ctx.beginPath();
    ctx.arc(0, 0, r, 0, Math.PI * 2);
    ctx.fill();

    ctx.restore();
  }
}

Option B: Using an External PNG, WebP, or SVG Image File

To use an image file (e.g., from public/assets/...) instead of procedural vector drawing, modify the createTexture method in HeroToolsScene.ts to draw an image onto the canvas texture: 

// Example: Loading an image inside createTexture() in HeroToolsScene.ts
if (tool.imageSrc) {
  const img = new Image();
  img.src = tool.imageSrc;
  img.onload = () => {
    // Draw centered on 1024x1024 badge face
    ctx.drawImage(img, c - 180, c - 240, 360, 360);
    texture.needsUpdate = true;
  };
}

3. Adjusting Physics, Speeds & 3D Behavior

The physics engine in HeroToolsScene.ts runs in the updatePhysics(dt) method and pointer event handlers. You can fine-tune every physical force:

Behavior / Feature Code Location Parameter & Default How to Adjust
Centering Gravity (Orbit) updatePhysics() b.velocity.x += -b.position.x * 0.38 * dt
b.velocity.z += -b.position.z * 0.55 * dt		 Increase multipliers (e.g. 0.8) to snap chips faster toward center; decrease (e.g. 0.15) for wider, looser floating orbits.
Air Drag (Deceleration) updatePhysics() b.velocity.multiplyScalar(Math.pow(0.88, dt)) Change 0.88: 0.75 makes chips slow down quickly; 0.95 lets chips coast smoothly for longer distances.
3D Tumbling & Spin Speed applyImpulseToAll() & onPointerDown b.angularVelocity.set((rand - 0.5) * 9.0, ...) Multiply or divide the multiplier (e.g. change 9.0 to 16.0 for high-spin action or 4.0 for gentle roll).
Spin Damping updatePhysics() b.angularVelocity.multiplyScalar(Math.pow(0.86, dt)) Controls how long a chip continues to tumble after being struck before it settles.
Upright Spring Factor updatePhysics() b.angularVelocity.x += -tiltX * 0.55 * dt Controls how strongly a chip coaxes itself back to face the camera after tumbling. Higher = snaps upright fast; lower = stays tilted longer.
Collision Bounciness updatePhysics() const restitution = 0.82; Set between 0.1 (completely inelastic thud) to 0.95 (super elastic bouncing).
Collision Spin Torque updatePhysics() const torqueMag = impulseMagnitude * 0.18; Controls how much angular spin is transferred when two chips strike each other in 3D.
Maximum Speed Cap updatePhysics() b.velocity.clampLength(0, 18.0); Prevents chips from escaping the container during rapid consecutive mouse tosses or multiple scatter clicks.

4. 3D Depth & Container Boundaries

The boundary box is calculated dynamically in getBounds() in HeroToolsScene.ts: 

public getBounds(): { boundX: number; boundY: number; minZ: number; maxZ: number } {
  const vFov = (this.camera.fov * Math.PI) / 180;
  const visibleHeightAtZero = 2 * Math.tan(vFov / 2) * this.camera.position.z;
  const visibleWidthAtZero = visibleHeightAtZero * this.camera.aspect;

  const boundX = (visibleWidthAtZero * 0.5) * 0.84;
  const boundY = (visibleHeightAtZero * 0.5) * 0.80;
  
  // 3D Depth boundaries
  const minZ = -5.5; // Deepest distance away from camera (smaller scale)
  const maxZ = 4.2;  // Closest approach to camera (larger scale)

  return { boundX, boundY, minZ, maxZ };
}

5. Background Vignette Shader & Color Palettes

The background is rendered inside WebGL using a custom vignette shader quad (bgMesh) with noise dithering and mouse interaction. Clicking any chip or the deck canvas advances through the palettes array: 

private palettes = [
  { c0: new THREE.Color('#141d3d'), c1: new THREE.Color('#05070f') }, // Midnight Navy
  { c0: new THREE.Color('#0c2b25'), c1: new THREE.Color('#030e0c') }, // Emerald Obsidian
  { c0: new THREE.Color('#24113a'), c1: new THREE.Color('#0b0514') }, // Imperial Violet
  { c0: new THREE.Color('#2b0e1d'), c1: new THREE.Color('#0e0409') }, // Crimson Velvet
  { c0: new THREE.Color('#261a0c'), c1: new THREE.Color('#0e0803') }, // Royal Bronze / Amber
  { c0: new THREE.Color('#0c2534'), c1: new THREE.Color('#030d15') }, // Cyan Abyss
  { c0: new THREE.Color('#1b1e28'), c1: new THREE.Color('#080a0e') }, // Graphite Slate
];

To add or customize palettes: Add or edit hex values in the array above. c0 controls the center spotlight color, and c1 controls the outer edge vignette shadow. The transition speed is set in startLoop(): 

// Adjust color interpolation speed (dt * 3.5 = ~0.3s transition)
this.currentColor0.lerp(this.targetColor0, dt * 3.5);
this.currentColor1.lerp(this.targetColor1, dt * 3.5);

6. Layout Modes: Full Deck vs 40/60 Split

The section supports two display modes without breaking existing pages:

  • Full Deck (Default): Full-bleed 3D physics stage with header and HUD overlay cards.
  • 40/60 Split Mode: Left 40% column dedicated to title, subtitle, CTAs, and active HUD card; right 60% column dedicated to the 3D scene.

To change the default layout in Astro: 

<!-- Full Deck (Default) -->
<HeroTools layout="full" />

<!-- 40/60 Two-Column Split Mode -->
<HeroTools layout="split" />

You can also test split mode interactively at any time by appending ?layout=split to the URL: http://localhost:4321/hero-tools?layout=split, or using the interactive toggle buttons in the top-right preview banner.
