Project Architecture & File Structure Breakdown

In-depth technical breakdown of the 196 source files, 33 static pages, modular runtime architecture vs. legacy monolith, and dev server troubleshooting.

1. Key Project Metrics

⚡
196 Source Files
Organized across Astro pages, modular CSS stylesheets, 3D WebGL scenes, and decoupled UI controllers.
📄
33 Static Routes
Built in ~1.1 seconds via Astro SSG, including 19 detailed project case studies and 6 specialized service verticals.
🧩
48 Runtime Modules
Deconstructed from the original 26,946-line monolithic runtime.js into 11 clean, maintainable domains.

2. Core Technology Stack

  • Astro 7+: Static Site Generator (SSG) delivering pure HTML shells, fluid responsive layouts, and zero client JS overhead by default.
  • Three.js (Custom WebGL Engine): Persistent single WebGL canvas (canvas#canvas) handling Jacks rigid-body collisions, Voronoi glass space tunnels, lunar terrain displacement, and FLIP fluid simulations.
  • Post-Processing Pipeline: Dual-pass Gaussian Blur, HDR Bloom pyramid, Subpixel Morphological Anti-Aliasing (SMAA), Screen Paint distortion, and AMD FidelityFX Super Resolution (FSR) upscaler.
  • Client-Side SPA Coordinator: RouteManager.js + PageManager.js intercepting internal links to transition pages smoothly without WebGL context loss.
  • SplitType & Tween: Kinetic typography word/character rollups with garbage-collection safe DOM reverters.

4. Monolith vs. Modular Runtime Deconstruction

Originally, the client WebGL experience was contained in a single 27,000-line file (src/scripts/runtime.js). While functional, debugging a shader pass or modifying a UI preloader required navigating massive complexity.

We deconstructed the runtime into 11 focused domains inside src/scripts/runtime/:

Domain Path File Count Responsibilities
src/scripts/runtime/core/ 11 modules Math utilities (clamp, lerp, fit), browser capability detection, viewport dimensions, dynamic spring physics, mouse/touch raycasting.
src/scripts/runtime/webgl/ 13 modules Root Three.js App renderer, FBO ping-pong buffers, SMAA anti-aliasing, Bloom passes, FSR upscaling, and SVG path triangulators.
src/scripts/runtime/scenes/ 5 modules Physics rigid-body Jacks hero, Space Tunnels with Voronoi glass, lunar landscape terrain, FLIP fluid simulation, and 3D product showcase.
src/scripts/runtime/ui/ 8 modules Header navigation, animated link hover underlines, Showreel Vimeo modal, Preloader counter, and TransitionOverlay.js (Brand K preloader & live debugger).
src/scripts/runtime/navigation/ 11 modules Virtual smooth scrolling manager, SPA RouteManager, PageManager coordinator, and individual page lifecycle controllers.

5. Dev Server Commands & Troubleshooting

Helpful commands for local development:

Starting the Astro Development Server

# Standard start
pnpm dev

# If another server is occupying port 4321 or 4322, replace it with force:
pnpm dev --force

# Or specify an alternate open port:
npx astro dev --port 4325

Resolving "Another astro dev server is already running" Error

Port Conflict Resolution
If Astro reports "Another astro dev server is already running on PID XXXX", you can cleanly stop it from the terminal without killing processes manually: 
npx astro dev stop
Or run astro dev --force which automatically shuts down the old background instance and claims the port.
