SectionRegistry & Component Lifecycle

How interactive 3D sections are dynamically discovered, mounted, updated on animation frames, and cleanly detached.

1. The Section Lifecycle Contract

Every interactive section controller in src/scripts/runtime/sections/ adheres to a standard interface:

Method When Invoked Responsibilities
preInit(container, hostPage) Page mount / DOM attached Queries section DOM elements, initializes WebGL meshes, and parents meshes to hostPage.preUfxContainer.
init() Page enters active state Binds global listeners, allocates WebGL shader textures, starts video streams.
resize(width, height) Window resize & page reveal Re-splits text (SplitType), computes responsive canvas/element dimensions, caches DOM bounding rects.
update(dt) Every animation frame Calculates scroll progress, transforms 3D objects, updates GLSL uniforms.
hide() Navigating away Resets text states, pauses active video elements, silences audio buses.

2. How SectionRegistry Works

Rather than hardcoding section references into pages, SectionRegistry.js scans the active page DOM for matching CSS selectors:

src/scripts/runtime/sections/SectionRegistry.js 
// Example registration
sectionRegistry.register("#home-hero", () => window.homeHeroSection);
sectionRegistry.register("#home-reel", () => window.homeReelSection);
sectionRegistry.register("#home-goal", () => window.homeGoalSection);
sectionRegistry.register("#home-featured", () => window.homeFeaturedSection);

When a page mounts, SectionRegistry.detectSections(domContainer, hostPage) runs. If a selector is absent from the DOM, that section controller is completely omitted from the animation loop, saving CPU and GPU cycles.

3. Complete Section Elimination & Tree-Shaking

To permanently eliminate a component from the site:

  1. Remove the component tag (e.g. <Goal />) from your .astro page templates.
  2. Unregister its selector in src/scripts/runtime/sections/index.js.
  3. Delete the component folder in src/components/.
